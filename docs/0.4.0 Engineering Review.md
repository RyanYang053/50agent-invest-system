# Engineering review — research runtime 0.4.0

## Status and scope

This release advances the 3.0 reference core toward a usable research application; it is not a production-certified fund or trading system. All external trading remains disabled. Fifty logical roles are not fifty deployed services. No real brokerage login, paid inference, live source request or market backtest was executed during offline verification.

## Model policy

Deterministic Python first for financial arithmetic, timestamp/identity checks, risk gates, accounting, and policy. Use cheap certified models for extraction/classification; DeepSeek Flash is a candidate for routine reasoning, OpenAI Sol for material ambiguity and complex synthesis, Claude Sonnet as an independent challenger. Gemini Flash and local models remain candidates, not supported/certified production adapters in this release. The existing registry defines planned role assignments; eligibility is not a benchmark result. Uncertified providers must not silently fall back to an expensive model. Select lowest measured cost among models meeting a role's minimum quality/privacy/latency criteria. Refuse unsupported tasks rather than fabricate output. Scope labels and trusted operator-supplied public queries must be enforced by the deployment boundary; never paste private balances into public prompts. Citation membership does not establish entailment.

Provider specs: https://openai.com/api/pricing/ ; https://api-docs.deepseek.com/quick_start/pricing ; https://platform.claude.com/docs/en/about-claude/pricing ; https://ai.google.dev/gemini-api/docs/pricing . Recheck before paid use; provider IDs, rates, and entitlements change. No API budget is authorized by this document.

## Tool coverage and priority

Actual modules: `research`, `market_data`, `feeds`, `transport`, `pipeline`, `ledger`, `retrieval`, `documents`, `decision`, `risk`, `ibkr_bridge`, `models`, `runtime`, `events`, `scheduler`, `learning`, `evaluation`, `backtest`, `licenses`, `release`. The role manifest is a target contract, not a guarantee of availability: macro/news, portfolio analytics, option and tax analysis, execution drafts, security checks and full event-specific workflows still need complete typed adapters and acceptance tests. Never expose general shell execution or real order placement to an agent. Owner policy changes and strategy promotion stay outside AI authority.

## Verification and deployment gates

1. Offline regression, compile and synthetic smoke (this release).
2. Explicitly approved provider credentials and license matrix; SEC and IEX integration with timestamps, independent field reconciliation and failure tests. Sources: https://www.sec.gov/search-filings/edgar-application-programming-interfaces ; https://docs.alpaca.markets/docs/about-market-data-api .
3. Locked financial model/RAG evaluation using rights-cleared data and no future-answer leakage. Calibrate cost, accuracy, abstention and citation correctness; independently review before certification.
4. Obtain complete historical universe and corporate actions with suitable usage rights; walk-forward, transaction costs, multiple-testing controls, risk-matched benchmark comparison. Replay alone cannot prove alpha.
5. Local-only all-account IBKR read-only acceptance, stale/partial snapshot and margin stress testing. Never conflate buying power, cash and liquidity.
6. Prospective shadow monitoring with independently resolved forecasts, fixed benchmark and no orders; review decision quality and realized outcomes separately.
7. Release only validated changes through human approval, versioned artifacts, rollback and audit. No claim of complete production readiness until each gate is evidenced.
