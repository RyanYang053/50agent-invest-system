## Controls added

1. Benchmark artifact joins: the four role artifacts must be distinct and independently hash-verified. JSON testset `{"cases":[{"id":...,"input":...,"evidence_hash":...,"negative":...}]}` has exactly the signed case IDs and distinct exact inputs. Answer artifact `{"answers":[{"id":...,"output":...}]}` covers each case once. Rubric has a version and five named dimensions. Raw review must contain exactly the signed case rows. Evidence files may be reused if cases genuinely share a primary source; that is not permission to reuse the same question. Import rejects incompatible older reports. The runtime hash change invalidates earlier role certifications. These checks detect exact duplicates and structural mismatches, not paraphrased duplicates, reviewer collusion or factual correctness. Independently adjudicate quality and holdout construction.
2. L6 gates: require integer counts, check claimed evidence years and elapsed full XNYS sessions against the reviewed interval, require actual referenced benchmark/cost/trial/return artifacts, compare role case counts and evaluation period. This is an upper-bound chronology check; an interval with enough sessions is not proof that trading actually took place.
3. RAG: verify returned security identifier, scope and PIT boundary. Recompute document content hashes before returning text. An administrator with full local DB access can still modify both content and stored hash; independent backups/attestation remain needed. Benchmark checks do not demonstrate semantic entailment.
4. A075: require actual label availability <= evaluation cutoff, purge using that time, reject missing evidence time and future signal dates; return insufficient data if no valid fold. Actual provenance still requires qualified sources.
5. Trial registry: bind planned requests, exact split, dataset, policy, attempt/result hashes and timestamps. Reject overlapping stable holdout sample IDs across campaigns and repeated attempts. Keep interrupted trials visible, record failures, do not delete or promote. Use consistent observation IDs (aliases and alternative databases can evade this local check). A local privileged operator can rewrite SQLite; external timestamping and independent trial-completeness audit are still required.

```bash
python -m pytest -q
python -m atlas_pro.public_acceptance

python -m atlas_pro.paper_replay

```

`atlas-public-audit --output /private/new-report.json` writes a new developer-only report; existing files are never overwritten. The CI executes the public and synthetic smoke on all three Python test jobs. For independent validation use `atlas-l6` with a private trust store, actual signed review artifacts, release/mandate hashes and per-role records. No real reviewer keys are shipped.
