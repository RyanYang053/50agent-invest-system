# Macro source refresh (developer candidate)

BLS is now an executable provider adapter, using the documented single-series
GET signature and only two hard-coded monthly public series (unemployment and
CPI-U). See https://www.bls.gov/developers/api_signature_v2.htm and
https://www.bls.gov/opub/copyright-information.htm for API and publication
policy. Check the provider terms before enabling the explicit series rights.

```bash
atlas-core refresh-macro --data-dir /private/atlas --macro-policies /private/macro-policies.json --network
```

The same policy list can be passed to screen-research. Example one policy:
```json
{"series_id":"LNS14000000","license_id":"BLS_PUBLIC","permitted_for_personal_analysis":true,"allow_local_retention":true,"allow_rag_indexing":true,"cloud_allowed":true}
```
Wrap policies in an array, and verify those rights before use. ALFRED uses an
operator-owned FRED_API_KEY. Bank of Canada Valet and BLS do not need a key for
these bounded public calls. The new standalone refresh may be invoked by an
operator-owned scheduler, but no scheduled job is created by installing Atlas.

The BLS observations are dated by actual UTC receipt; the adapter does not
reconstruct historic vintages or claim pre-release surprise data. It rejects
wrong series, warnings, malformed or future observations, and invalid values
before writing any rows. Annual averages do not enter the monthly series.
Only A063 can receive BLS data through the public model runner; the exclusion
is applied before shared macro lexical ranking. An optional external vector
backend is bypassed for that filtered macro query because its interface
cannot guarantee pre-ranking exclusion. Other local/operator index callers
are not an OS sandbox. No raw credentials or broker functions are exposed.

Tests use provider-shaped synthetic values, not live observations. Actual
provider availability and data quality are unverified. No paid call or trade.
Remaining resources are not certified as integrated merely by this adapter.
