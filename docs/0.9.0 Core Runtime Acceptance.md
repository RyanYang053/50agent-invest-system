# Atlas 0.9.0 — Core runtime and acceptance gates

Base: `b1581d4d107a18fe78059f6bdae5a35c8f7d12db` (merged 0.8). This is an incremental research-only release. Do not interpret 50 role routes as 50 certified autonomous agents. No account policy change, paid API call, private account upload, external paper order, or live order was performed. Prior independent GitHub CI results belong to 0.8; this release requires its own CI.

## What is executable

- `role_jobs.py`: complete manifest coverage (29 distinct fixed public research questions, 21 deterministic or local diagnostic/denial routes). Public jobs accept only canonical CIK or fixed macro identifiers. Role-specific, versioned task IDs prevent accidentally reusing a generic certification. Local jobs cannot call a model. Some local tasks intentionally stop (tax review, paper authorization); no local LLM is installed. The CIO and secretary tasks are bounded research memos, not automatic committee approvals. Specialized qualitative tasks require relevant original documents and true model/claim evaluation, not merely a prompt.
- `RoleJournal`: SQLite intent/result persistence, exact input hash, duplicate suppression, unresolved-request no-resend behavior; batch input hash frozen by run ID. Private state belongs in a local mode-0700 directory. Filesystem administrators can edit the database; hashes are not remote authentication. Resume unresolved work with independent review, never a new ID merely to bypass an uncertain paid call.
- `core_service.py`: one operator-driven run connects actual screen output to evidence resolution, candidate-specific role execution, and a WAIT result; optional recent filing and macro ingestion precede research. This does not automatically derive DCF assumptions, validate prose claim entailment, turn a memo into a committee attestation, or start paper orders. `atlas-workflow` remains the independent committee workflow. `atlas-shadow` and `atlas-paper` remain separate.
- `filing_ingest.py`: bounded fixed SEC Archives HTTPS requests from recent submissions metadata, contact identity, no redirect, primary filing only, basic HTML text/table separators, content and raw SHA-256, actual receipt timestamp. Does not retrieve exhibits or certify numerical table context. Current ingestion, not an historical archive; SEC can remove or correct filings. Keep permitted raw artifacts independently if archival reproduction is required.
- `macro_ingest.py`: current ALFRED vintages for DFF/DGS10/CPIAUCSL/UNRATE/GDPC1, BoC FXUSDCAD, per-series rights and provenance, actual receipt timestamps. Does not infer intraday historical release timing or validate economic forecasts. No private/license-only content may enter cloud index without specific permission.
- `account_risk.py`: requires exact operator-configured account roster, timestamped FX, signed balances/positions, per-account NAV tie-out, account type, market marks and margin observations. Independently calculates gross and net delta exposures, ETF look-through factor exposure, concentration and per-account scenario losses. Options require explicit metadata, underlying/Greek marks and nonnegative rate input; stress uses conservative instantaneous bounds conditional on the supplied shock and rate assumption, not a BSM or American option forecast. Per-account stress excess-liquidity approximation uses observed buffer plus P&L less explicitly shocked maintenance; it is not IBKR's house margin engine, and never nets collateral across accounts. Exact current ETF decompositions, options permissions, tax lots, broker what-if, and authenticated all-account capture remain acceptance requirements.
- `bench_runner.py`: fixed provider protocols, precommitted canonical testset hash, public authorized prompts without gold-answer fields, explicit per-run upper estimate, journal intent before requests, no retry on failure, strict response identity, numeric and citation grading. Output task ID is deliberately `atlas-numeric-role-*` (not a full `atlas-role-*` competency certificate). Real evaluations need role-specific locked tests with independently adjudicated qualitative correctness and appropriate rights. The existing certification primitive is numeric/citation-oriented; do not use it to certify broad qualitative competence by relabeling a numeric task. Evaluation budget is separate from research budget; pricing estimates are not a provider billing guarantee. No paid call is implied by local fixture tests.
- `runtime.py`: fixed Google Gemini REST adapter in addition to OpenAI, DeepSeek and Anthropic; exact returned model version required, thinking tokens included in budget reconciliation. Provider/model availability, supported thinking levels, API key, price and actual returned snapshot require live validation. Missing credentials and disabled network mode are filtered before reserving research budget.

## Run commands

From checkout, install `python -m pip install -e '.[market_calendar,test,quant,ml]'` and run `python -m pytest -q`. The catalog and readiness command do not contact any external service:

```bash
atlas-core readiness
atlas-core catalog --roles 'config/50 agent manifest.json'
```

`readiness` reports only credential presence, never secrets or authentication success. For real data, configure lawful data access and genuine SEC contact identity in the private operator environment. Use a new run ID for new evidence. The example policies are inoperable by design; review rights and create separate local copies. Paid inference is off by default; `--paid-models` requires explicit budgets and actual current role certifications.

```bash
atlas-core screen-research --network --run-id YOUR_UNIQUE_RUN_ID \
  --universe /private/universe.json --data-dir /private/atlas-data \
  --sec-policy /private/sec-policy.json --alpaca-policy /private/alpaca-policy.json \
  --roles 'config/50 agent manifest.json' --models 'config/model registry.json' \
  --basis ttm --max-candidates 3 --filings-per-company 2
```

Optional `--macro-policies /private/macro-policies.json` takes a list of explicit series-specific rights policies (`series_id`, `license_id`, `permitted_for_personal_analysis`, `allow_local_retention`, `allow_rag_indexing`, `cloud_allowed`). Never share portfolio data with cloud roles. `atlas-core run-role` takes an explicit role, input JSON, research cutoff and run ID, and saves the diagnostic locally. For model evaluation use `atlas-bench --help`; budget approval must be explicit, and no testset or answer is included in this public repository.

## Acceptance matrix

| Capability | Verified now | Remaining gate |
|---|---|---|
| 50 role task routes | catalog, dispatch/refusal and representative computation tests | real role-specific evidence, model competence and claim verification |
| SEC screen → public research batch | provider-shaped fixtures with persisted result | live source access, licensed quotes, primary docs, larger historical universe |
| Macro/filing RAG | local fixture ingestion and PIT retrieval | real corpus, full table context, accuracy and rights checks |
| Multi-account risk | synthetic CAD/USD, ETF and option stress tests | real authenticated roster, marks, Greeks, exposure look-through and IBKR what-if |
| Model competition | provider protocol, evaluation and cost gates tested | rights-cleared real testsets, actual API evaluation, claim-level scoring, costs and latency |
| Continuous learning | previous shadow/forecast and quant infrastructure | licensed real data and prospective outcome accumulation |
| Paper gateway | previous offline replay/CI | isolated broker paper session, actual fills/cancels/reconciliation, no autonomous paper orders yet |
| Live execution | intentionally disabled | separate future authorization/design and all acceptance gates |

Primary references checked for this implementation: SEC EDGAR API and fair access (https://www.sec.gov/search-filings/edgar-application-programming-interfaces and https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data); Google Gemini content generation response and token metadata (https://ai.google.dev/api/generate-content). No claim of investment alpha or production readiness from fixture counts.
