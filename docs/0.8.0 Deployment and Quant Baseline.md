## Quantitative research

Actual scikit-learn 1.8.0 Ridge and HistGradientBoostingRegressor train on a synthetic cross-sectional panel. Five expanding walk-forward folds, 400 predictions per model, no fit on test features/labels, scalers fit only on training samples, chronological date groups, training label availability strictly before test signal, explicit embargo, deterministic settings and recorded hashes. Outputs numeric predictions, rank IC, MAE and top-K forward-label diagnostics; no serialized executable model. Synthetic data's deliberately predictable relationship is not alpha or a backtest. Do not select a production champion using these results. Real panels need independently verified feature/label evidence and rights for BOTH training and evaluation; `training_authorized` is a local operator attestation, not proof. Dataset construction, licensed PIT history, survivorship, executable timing, fees, portfolio simulation and independent heldout validation remain real-data acceptance gates.

All times offset-aware. No private account data. Input file must be independently qualified before training. Do not upload licensed data to CI.

## OCI offline worker

Operator builds the vetted image in a separate environment with no private data or credentials. Base tag and transitive wheels are not hash-locked here; pin reviewed digests/hashes before formal deployments. No upstream generated code runs in this image. The runner requires a local immutable image ID, fixed entry point, no network, read-only root, non-root UID, dropped capabilities, no-new-privileges, no broker mounts or control socket, bounded CPUs/memory/pids/time/output, temporary input copy and read-only mount. Probe inside validates observed network, UID/capability status and mount state. Output is created without overwrite. Docker isolation does not replace host security; use disposable VM or independently hardened sandbox for untrusted generated code, and never let an agent control Docker. If Docker absent, refuse, no fallback.

```bash
docker build -f sandbox/Dockerfile -t atlas-research:0.8 .
image=$(docker image inspect --format '{{.Id}}' atlas-research:0.8)
bash sandbox/run-research.sh "$image" /private/synthetic-report.json
# approved operator data only:
bash sandbox/run-research.sh "$image" /private/report.json /private/panel.json FILE_SHA256
```

GitHub CI adds an actual Docker build and isolated synthetic run. No keys or licensed data. Locally executed network-namespace demo is only network isolation for trusted code, not an OCI or arbitrary-code sandbox acceptance.

## Daily shadow runner

`atlas-shadow --journal /private/shadow.sqlite tick-batch --plans /private/plan-ids.json --evidence /private/evidence.sqlite --licence /private/tiingo-policy.json --max-fetches 20 --network` accepts an explicit list of <=50 approved existing plan IDs. Run from one local scheduler/worker after 20:15 ET; only one pending session per plan per invocation. Shared observation versions are reused across plans and restarts; conflicting versions block, instead of silently selecting a new benchmark. Budget counts attempted provider reads, not billing. No future requests, no implicit zero returns, no automatic plan creation or retry. The runbook assumes one operator writer; cross-process quotas still need a deployment lock. API key, retention and corporate-action coverage must be independently authorized. Network adapter not exercised with live credentials here.

See https://github.com/scikit-learn/scikit-learn and https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html; Atlas uses stricter panel label-availability purging.

## Blockers to autonomous investment

No evidence that Atlas is strongest, profitable or ready for unsupervised execution. Actual model costs, accuracy and role qualification, real data and licensing, full historical universe, independently sourced financial feature evidence, risk across both IBKR accounts including leverage/options/FX, paper account identity and lifecycle, strategy-to-order authorization, and prospective operational testing are blocking gates. Real trading remains disabled. Research decisions remain WAIT, shadow is separate hypothetical experiment, paper only operator-approved. No credentials committed or deployment service installed on user machine.
