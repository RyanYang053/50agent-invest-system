# Atlas 0.5.0 — Controlled Paper Pilot and Readiness Audit

## Scope and evidence

Base: merged PR #2 (`6e356cf3b0a555f19d3c1a03d44a9fa2cacc4fc7`), prior GitHub CI passed. This release adds a separate operator-only paper adapter, persisted order intents, pre-send limits, reconciliation, kill switch and deterministic quote replay. It is not a live execution adapter, an automated trading strategy, or evidence of positive investment returns. IBKR remains read-only. All research and model outputs still have `can_trade=false`.

Local verification: 223 pytest cases and 3 subtests passed on the development environment, including 49 new cases; previous 174 cases still pass. Compilation and two offline demos passed. Fixtures are not external broker confirmations. No paper or live credentials were available in the development environment. No paid inference, actual market data or broker order was requested. Remote CI must pass before merge.

## Risk boundaries

- Fixed `https://paper-api.alpaca.markets` only. No configurable host, redirect following, proxy environment use, arbitrary order endpoint, live key fallback or POST retry.
- Separate `ALPACA_PAPER_KEY` and `ALPACA_PAPER_SECRET`; use only a newly created, isolated paper account. Account UUID and exact locally approved policy hash are bound to the SQLite journal. Keep journal and key directory private, outside the repo and outside LLM/MCP process permissions.
- Explicit arming, exact per-order operator confirmation and a persisted stop switch. Stop prevents subsequent sends, not an already in-flight request; manually cancel and reconcile open orders. No automatic restart/arming.
- US equities on explicit user-maintained allowlist only; operator must exclude leveraged/inverse products, non-equities and complex securities. The provider's US-equity asset class does not distinguish leveraged ETFs from ordinary equities. Whole shares, USD, day limit orders, regular session only; no shorting, margin borrowing, options, fractional orders, extended hours, market orders, replace or broker routing to live.
- Confirm dedicated account and active broker state. Fetch broker clock, asset, open orders, cash/equity and positions. Compare cash + long market value with equity, use max order, cash reserve, single-position and gross exposure constraints. Serial snapshots are non-atomic and this is not an IBKR margin/market-risk calculation. Do not use another client on the same paper account concurrently. Local DB transaction fences this gateway's workers only. Recheck before POST; one outstanding order at a time.
- Persist intent *before* POST. Duplicate ID returns journal state. Ambiguous acknowledgements remain unresolved and block further orders. Never automatically retry even on 404. Reconcile by client order ID. Verify broker identity and order fields, monotonic whole-share cumulative fills and fill price against limit. Cancel acknowledgement is not terminal cancellation. Terminal contradictory response disarms. Cumulative average price is stored; full per-execution activity/fees remain to be integrated. No guarantee of exactly-once execution at an external broker.
- Policy is local operator consent, not cryptographic identity authentication. Do not share the private path or broker keys with the research runtime. OS isolation and operator control are required. The separate paper policy does not override the user's investment mandate or authorize real trades.

## Start offline now

From the repository checkout:

```bash
python -m pip install -e '.[market_calendar,test]'
python -m pytest -q
python -m atlas_pro
python -m atlas_pro.paper_replay
```

The replay starts with $10,000 synthetic cash, places one fictional five-share limit order, does not fill at an ask above the limit, fills 2 and then 3 shares using subsequent fixture ask prices and displayed sizes, deducts $0.05 synthetic fees, and marks the portfolio at a fixture bid. Ending cash $9,500.10 and equity $9,999.10 are accounting assertions, not investment performance. Zero network and broker calls. It is a single-session replay, not an order-book exchange simulator or a complete historical backtest.

## First external Alpaca paper session (operator only)

1. Create a paper-only account at https://alpaca.markets/ and obtain the *paper* account UUID and paper API credentials. Never paste the secret in chat, logs, repository, or shell history. Set the two named environment variables locally through a secret manager. Keep the paper account separate from all live accounts. The connector does not automatically provision any credentials.
2. Copy `config/paper policy example.json` into an access-restricted private directory outside the repo. Replace the placeholder UUID, review the allowlist and limits, and only then set `owner_confirmed_paper_only` to `true`. Default example is intentionally inoperable. All risk limits here are conservative paper experiment ceilings, not personalized investment recommendations.
3. Use the same private directory for the journal. Authenticate with read-only inspection first. Confirm the account ID in the broker UI, cash, positions and that there are no open orders. Example syntax (replace paths):

```bash
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite --network-paper-only inspect
```

4. Only during regular US trading hours, after verifying a dedicated paper account and the operator's chosen order, arm explicitly. Prepare a private JSON file containing exactly `client_order_id` (prefix `atlas-paper-`, unique), `symbol`, `side` (`buy` or `sell`), `qty` (whole shares), and `limit_price` (USD cents; at least $1). Use a symbol permitted by the local paper policy and an independently verified price. The release intentionally supplies no real-symbol executable order. Keep a record of the reason for the manual smoke test; it is not a model signal.

```bash
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite --network-paper-only arm --confirm
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite --network-paper-only submit --order /private/paper-order.json --confirm
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite --network-paper-only reconcile atlas-paper-YOUR_ID
```

5. Compare the status, cumulative quantity and average price with the paper brokerage UI. For a remaining open order, explicitly cancel it, then reconcile again. Stop when finished, including if the network is unavailable:

```bash
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite --network-paper-only cancel atlas-paper-YOUR_ID --confirm
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite --network-paper-only reconcile atlas-paper-YOUR_ID
atlas-paper --policy /private/paper-policy.json --journal /private/paper.sqlite stop
```

If there is an unknown order, do not create a replacement ID to work around the unresolved state. Verify broker history with the operator; the gateway will continue blocking new orders. Do not delete the journal to bypass an unknown order. Policy/account changes require a new dedicated journal only after the old journal is reconciled and disarmed. Retain private audit records.

## Acceptance gates: independently verify before each advancement

| Gate | Status | Required evidence |
|---|---|---|
| A. Offline lifecycle | Passed locally | Limit bounds, partial fills, stale/out-of-order data, cash, shorts, cancel lifecycle, duplicates/concurrency, lost acknowledgement, failure to reconcile, kill switch. |
| B. Authenticated paper connectivity | Not run | Dedicated paper UUID, entitlement, position/cash reconciliation, real clock, account permission fields. |
| C. Broker paper lifecycle | Not run | Operator-supervised submit, query, partial/full fill or cancel, disconnect/restart, duplicate prevention and broker UI agreement. Test provider response schema with actual account. |
| D. Full independent strategy shadow | Not run | Real licensed PIT data, validated forecasts and candidates, decision IDs linked to shadow positions, daily benchmark/fees/FX, independent risk engine, scheduled outcome collection. Current decision grid remains WAIT; do not convert WAIT to an order. |
| E. IBKR paper integration | Not implemented | Explicit dedicated paper account verification, isolated TWS/IB Gateway session, actual callback and account identity tests, positions and order events, margin what-if, entitlement and jurisdiction checks. Port 7497/4002 alone is not evidence of paper mode. |
| F. Live trading | Disabled / not eligible | All preceding applicable gates, broker-specific risks and permissions, user mandate, separately designed secure execution service, live small-size review. No live route in this code. |

The prior IBKR read-only bridge now enforces a <=300-second broker capture, rejects future timestamps, and requires reconciliation snapshot IDs to match both exact snapshots. A Flex report date is not an atomic live broker timestamp; `same_asof` remains false. No exact trade size based on that bridge alone.

## Remaining architecture work

- Verify each of the 50 role/tool routes with real financial cases. Model certifications must use authorized, frozen evaluation data, not just declared model names. The current certified model gateway and researcher are not an automatically complete investment committee.
- Connect data feeds, provider entitlements, corporate actions, benchmark series and historical universe coverage; qualify NBBO/execution-relevant feeds separately from IEX research.
- Complete RAG retrieval quality, embeddings, full filing tables/notes, licensed content isolation and evidence-level fact validation. Record published/available timestamps and revisions.
- Paper fills must be joined to actual decision and forecast IDs, broker per-execution activity and portfolio attribution. Add continuous read-only reconciliation, alerting, strategy-level limits and stop/recovery tests before automated paper trading.
- Run a prospective 20–60 trading-day operational shadow pilot as an initial reliability window; performance/probability evidence for long-horizon strategies needs much longer, diverse market regimes and sample-size-aware tests. This is a recommendation, not an elapsed test.
- No model may amend the risk policy or promote a strategy on its own. No guarantee of avoiding losses, matching actual fills, or beating a benchmark.
