# Atlas 0.7.0 — prospective research, measurement and acceptance

Base: PR #5 merged at `aeb205d2d11ae6480c5f90405f3b9c6650a651b9`. The 0.6.1 baseline was reconstructed from the original hash-pinned source transfers and reproduced 282 passing tests, 3 skipped optional packages and 3 passing subtests. 0.7.0 local suite: 324 passing tests (42 added), 3 skipped optional packages, 3 passing subtests. Tests use fixtures; no paid inference, external market-data request, broker session or order. No live execution, no automatic paper orders, no user mandate changes.

## What is now executable

- `ShadowJournal`: require a complete checkpointed research-only committee run with an independently calculated, matching risk result; freeze hypothesis, asset universe, weights, cost assumption, data-source bindings, benchmark and real exchange sessions before anchor close. The hypothetical target is a distinct experiment, not authorization to act on a WAIT decision. Same-policy risk refresh permits a fresh snapshot after deliberation without rewriting the original committee decision. USD cash-equity scope only.
- Read-only Tiingo EOD adapter: explicit local entitlement, fixed HTTPS host, no redirect or proxy, exact adjacent exchange-session coverage, source and ticker binding, raw response hash, local evidence records. Fetch both adjusted closes in one request after 20:15 New York time; receipt time is availability (not an invented historical release time). Source: [Tiingo EOD documentation](https://www.tiingo.com/documentation/end-of-day), checked 2026-11-23 ET. The provider describes CRSP-based split/dividend adjustments and possible evening corrections. The ratio is a **provider-specific total-return proxy**; it is not independently verified corporate-action accounting. Operator approval attests reviewed data coverage; independently validate spin-offs, delistings, symbol changes and corrections. Missing/ambiguous data blocks the next session; never fill with zero. No training rights are granted by this template. Respect subscription limits and retention terms; never distribute data.
- Shadow daily ledger: resolves each observation against authoritative evidence identity, timestamp, source, license and hash; stores immutable sequential hash-linked observations, drifts weights as a buy-and-hold notional, applies explicit inception transaction-cost haircut, assumes zero cash interest, computes paired benchmark metrics. No actual shares, fills, external flows, margin, tax or execution slippage. Exact session sequence (holidays and early closes), no backdating or silent gaps. SQLite protects against normal corruption, not a privileged attacker rewriting the database and hashes. Evidence authenticity is not proven by a hash or an operator flag.
- Freeze an optional subjective excess-return probability before the anchor. At completion score the hit and Brier loss against a baseline; one forecast is not calibrated skill. Synthetic runs never qualify a strategy.
- Compare distinct prospective strategy versions only on identical full session sequences, same policy hash/cost rate/benchmark, matching data bindings and exact benchmark evidence version. Reuse the same benchmark evidence IDs across plans using local `append`. Independent moving-block bootstrap with declared trial-count correction; fewer than 100 or too-dependent observations reject. Proxy data and trial completeness still need independent qualification. No promotion or deployment.
- Actual fixed model transports require regraded non-synthetic locked cases (at least 100), zero critical citation/abstention failures, every response present, correct returned model ID, role-dependent 90/95/98/100% minimum quality (engineering thresholds, not predicted investing skill), matching role/config hash and expiry <=90 days. `atlas-certify` ingests hash-pinned external artifacts; the operator must verify genuine provider output, dataset rights, held-out case identity and precommitment. An old self-reported scalar certificate cannot authorize the fixed network transport. Compatible, measured challengers can compete beyond the static pair; cost estimates use current UTC billing time, not historical PIT cutoff. Registry change invalidates the measured certificate. Certificate is rechecked under reservation lock; an already reserved in-flight call is not retroactively revocable. Exact provider ID match is deliberately conservative: update and evaluate resolved version if alias responses differ. No paid inference in this release.

## Local deployment sequence

Install audited dependencies in a private environment. Do not use a repo checkout as a secret/data directory; do not grant research models shell, journal write, broker or secret access.

```bash
python -m pip install -e '.[market_calendar,test,quant]'
python -m pytest -q
atlas-workflow --help
atlas-shadow --help
atlas-certify --help
python -m atlas_pro.paper_replay
```

Run `atlas-workflow` using a qualified local evidence ledger and authorized research packet; complete the independent bull, bear and verification attachments. Do not fabricate approval or source data. The committee returns WAIT. A separate operator may choose a hypothetical shadow experiment, not an order. Plan JSON requires exactly `targets`, `benchmark`, `source_bindings`, `anchor`, `end`, `cost_bps`, `synthetic`; optional `forecast` (`probability`, `baseline_probability`, `excess_return_threshold`) and `risk_refresh` (`policy`, `snapshot`, `returns`, `clusters`, `stress_scenarios`). Targets must match the independently computed risk target hash. Anchor/end are XNYS session dates, anchor strictly future close. For Tiingo, each nonzero target and benchmark must have a stable security identity mapped by the operator to `{source_id: "tiingo_eod", license_id: "TIINGO_EOD_PERSONAL", data_class: "licensed", ticker: "..."}`. Never use unreviewed ticker identities. The separate private policy template is in `config/Tiingo policy example.json`, disabled by default. Only use `synthetic: false` with real authorized source data.

```bash
atlas-shadow --journal /private/shadow.sqlite start --committee /private/committee.sqlite --run-id RUN_ID --plan /private/plan.json --confirm
atlas-shadow --journal /private/shadow.sqlite report PLAN_ID
# After 20:15 ET on each session, explicit local operator or OS scheduler; no external service is installed by this repo.
atlas-shadow --journal /private/shadow.sqlite tick-tiingo PLAN_ID --evidence /private/evidence.sqlite --licence /private/tiingo-policy.json --network
# Or use shared, verified ledger observations imported by the operator:
atlas-shadow --journal /private/shadow.sqlite append PLAN_ID --evidence /private/evidence.sqlite --observation /private/observation.json
atlas-shadow --journal /private/shadow.sqlite compare CHAMPION_ID CHALLENGER_ID --trial-count NUMBER --max-drawdown APPROVED_FRACTION
```

Keep `TIINGO_API_KEY` in a local secret manager/environment, never in chat, logs or a public repo. `tick-tiingo` fetches one next interval and up to 100 risky assets plus benchmark; review quota before scheduling. Use one operator worker; if a request fails, do not invent data. Resume missing interval first. Provider revisions can occur; do not silently rewrite past scored observations. For competing strategies, import one shared benchmark record into both plans rather than refetching it independently. The CLI has no order commands. The separate `atlas-paper` pilot remains operator-only; use the 0.5 runbook for authenticated simulated broker testing, not for autonomous strategy execution.

## Model admission workflow

Use Inspect AI or another isolated evaluation runner on a frozen licensed case set. Case records must match `grade_locked`; exclude expected answers from model prompts. Produce answer objects keyed by case_id with `returned_model`, `values`, `evidence_ids`, `abstain`. The CLI hashes the exact source files and independently regrades; the canonical case-set hash must be committed before the trial. Returned IDs must be genuine provider output, not manually invented. The operator, not the research model, runs certification.

```bash
atlas-certify --registry 'config/model registry.json' --roles 'config/50 agent manifest.json' --journal /private/models.sqlite --cases /private/locked-cases.json --cases-sha256 CASE_FILE_HASH --answers /private/answers.json --answers-sha256 ANSWER_FILE_HASH --locked-hash PRECOMMITTED_CANONICAL_CASE_HASH --role ROLE_ID --model REGISTRY_ID --task-set TASK_SET --valid-until EXPIRY_TIMESTAMP --confirm-independent-evaluation
```

Legacy fixture certificates are retained for offline tests only. No actual case set or API response was created during 0.7 development. Engineering thresholds test structured numeric/citation membership, not general prose faithfulness, forecasting ability or an empirical alpha edge. Before selecting a production role model, also measure latency, actual provider billing, robust source support, prompt injection and failure recovery.

## Release gates and honest status

| Gate | 0.7 status | What still needs external evidence |
|---|---|---|
| Research computation and durable lifecycle | Locally tested, provider-shaped fixture inputs | Real issuer statement/TTM tie-outs; independent thesis claim review |
| Locked role/model admission | Regrading and billing clock enforced by fixed network runner | Real authorized benchmark set, exact model/API IDs, paid trials, actual cost/latency, 50 role/task certifications |
| Shadow forward performance | Executable and tested | Real licensed EOD ingestion, stable security universe, benchmark/corporate-action tie-out, prospective observations over time |
| Strategy evolution | Paired evidence gate and proposal, no auto-promotion | Real isolated Qlib/RD-Agent/LEAN experiments, independent holdout and trial history |
| RAG | Existing local hybrid search, optional Qdrant/DuckDB/skfolio tests in CI | Actual filing corpus, Docling/EdgarTools parsing, real retrieval/faithfulness evaluation, production embedding assets |
| Broker paper | Separate prior gateway, offline lifecycle verified | Dedicated authenticated Alpaca paper session, order/query/cancel/fill and recovery validation; link actual executions and fees to independent research logs |
| Full IBKR | Read-only snapshot bridge | Actual all-account reconciliation, option/FX/margin/leverage/tax risk, broker paper account identity and callbacks |
| Autonomous paper/live | Disabled | All applicable gates, independent full portfolio risk and order-specific authorization; no live route |

No amount of unit tests substitutes for these live data, model, market or elapsed-time tests. Use versioned, independently qualified evidence and refuse missing inputs. Do not enable autonomous paper or real orders based on this release.
