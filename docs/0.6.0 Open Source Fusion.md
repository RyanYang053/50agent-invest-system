# Atlas 0.6 — Open-source-informed research workflow

Base: merged paper pilot PR #3, `f6bfa7214ed38d4128361c548902bd67b3110909`. Local baseline source blobs matched the remote tree (except `.gitignore` which is preserved remotely). No licensed data, secrets, actual portfolio or executable third-party code added.

## Architecture and adoption choices

See `config/open source integration catalog.json` for 18 reviewed projects, reported licenses, actual adoption status and acceptance gate, and `config/workflow role coverage.json` for all 50 roles. GitHub metadata checked on 2026-11-23 ET (some UTC timestamps are November 24). An active repository or permissive code license does not prove research quality, data access or model weight rights. No vendored upstream code. NumPy/SciPy are the only newly used dependencies, behind the `quant` extra. The remaining projects are architectural references or candidates for isolated integration, not installed libraries. Keep the system lean: a mature library only replaces an Atlas component if its real-task correctness, maintenance burden, resource cost and permission boundaries improve. No unverified remote code execution.

## Reproducible workflow

Install from repo checkout: `python -m pip install -e '.[market_calendar,test,quant]'`, then `python -m pytest -q`. The `quant` extra is optional for the core but CI installs it and actually exercises SciPy. All tests use synthetic/provider-shaped fixtures. No external requests are part of the tests.

1. Operator runs `atlas-screen` with authorized data. Its explicit input universe remains 1–100 securities; new sector factor ranking accepts a separately prepared factor cross section, not a complete market. Externally supplied quote and share values must match exact ledger payloads, not merely any evidence IDs. DCF candidate quote and cutoff are checked against the candidate.
2. Operator prepares a private JSON packet with `cik`, `decision_at`, `strategy_version`, approved policy, `fundamental_ids`, `market`, DCF `assumptions`, `terminal_scenarios`, `benchmark_return`, `portfolio`, `target_weights`, `aligned_returns`, `clusters`, `stress_scenarios`. See the fixture in `tests/test_research_runtime.py` for the complete executable shape. Never commit a real packet. `atlas-workflow PACKET --evidence PRIVATE_EVIDENCE_SQLITE --journal PRIVATE_COMMITTEE_SQLITE [--attachments PRIVATE_ATTACHMENTS_JSON]`.
3. The workflow freezes the base packet hash. It independently rebuilds the annual financial snapshot and screen from the stored ledger, verifies price/share evidence and computes valuation. It stops at the first missing handler. Bull and bear attachments are `RESEARCH_MEMO` records with distinct `researcher_id`, `claim`, public ledger `evidence_ids`, and `can_trade:false`. No private portfolio is included in model prompts. IDs do not prove human identity or claim entailment. An independent reviewer must verify actual content and supply `status:VERIFIED`, `claims_verified:true`, a distinct reviewer ID and exact hashes of fundamental, valuation, bull and bear stages. These are operator attestations, not authenticated identity assertions.
4. Only after review, independently recompute cash-equity risk from supplied reconciled snapshot, timestamped quotes, aligned total-return scenarios and approved limits. Portfolio optimization is a research tool, not an execution plan. It minimizes sample CVaR with explicit return floor and cash/single/cluster constraints; it does not optimize turnover, fees, taxes or liquidity. The independent risk review checks turnover and stress separately. No short, margin, options, leveraged ETFs or currency conversion supported by this new risk engine. Return horizon and source quality must be established by operator; risk limits must be independently approved and not inferred from model output. Old `ResearchRiskGate` remains a legacy advisory threshold check; it is not the authoritative source of risk calculations in the new packet workflow.
5. Decision stays `WAIT` and `position_size:null`, including when synthetic fixtures pass risk review. Terminal probabilities are unvalidated. No research stage can call the paper gateway or place an order. Postmortem plan remains a plan, not a fabricated forecast. Use the existing forecast journal only for actual prospective forecasts. Missing data, unsupported asset or failed risk blocks progress; do not bypass by changing packet hashes or claiming a new identity.
6. External experiment request contains engine, artifact/data/split/policy hashes, budget, timestamp. The `split_sha256` for report review is the hash of ordered locked test observation IDs. The separate worker must lock underlying train/validation/test data independently, verify licensing, resource limits, code and provenance, run non-networked except narrowly authorized data retrieval, and never have brokerage credentials. Atlas does not launch external code. Normalized report must echo hashes and engine/mode, actual cost, synthetic flag, and exact ordered observations (`id`, `at`, `net_return`, `benchmark_return`, `evidence_ids`). Reject missing rows, bad return paths, over-budget reports or synthetic claims as promotion candidates. Even a good report is only `INDEPENDENT_REVIEW_REQUIRED`. No return series is certified by schema/hash alone; independent experiment attestation, trial accounting, statistical uncertainty, regime coverage, forward paper performance and signed release are still required.

## Fixes and limitations

- Old RAG vector scan silently omitted eligible vectors beyond 5,000. Version-tagged vectors only; anonymous/legacy vectors remain lexical-only, and reindexing is required to use their embeddings. Over-capacity raises a specific error instead of returning incomplete results. Private and licensed embedding callbacks remain local-only. Existing SQLite scope checks remain.
- Continuous P0 signals previously reset the sliding debounce on every arrival and could suppress re-entry indefinitely. Fixed-window deduplication permits a new deterministic risk task each five-second window. This is still a queue, not a real-time interrupt or emergency cancel service.
- A valid evidence ID for an unrelated fact no longer suffices for price/share admission. Exact payload lookup and hash/time verification are independent of recency limit. Source correctness, ingestion authorization and issuer-level share class ambiguity still require verification.
- Do not interpret supplied probabilities, empirical CVaR, stress shocks or factor scores as validated alpha. External real model comparison, full TTM/industry accounting, macro/event streams, automated outcome collection, robust multi-account margin/tax, real broker paper connectivity, production RAG, historical security master, independent sandbox, experiment execution and full 50-role live handler coverage remain open. No all-in-one framework solves these problems. No dependency installation or network research tool is implicitly authorized by this release.
